# 아침 컨디션 기록

- 오늘 화면에서 컨디션(활력)·수면 만족도·아침 발기 여부·메모를 기록합니다. 숫자는 기존과 같은 1~5단계이며 모든 항목은 선택입니다.
- 선택한 답을 다시 누르면 해제됩니다. 상세 기록을 접어도 스트레스·성욕·자신감·생활습관 응답은 유지됩니다. 아무 응답도 없으면 저장할 수 없습니다.
- 최근 7일은 시스템 시간대의 오늘을 포함합니다. 미기록과 미응답을 구분하며 기존 날짜별 기록은 수정·삭제할 수 있습니다.
- 저장과 삭제는 저장소 완료를 기다립니다. 실패하면 입력 또는 기존 기록을 유지하고 재시도할 수 있습니다. 중복 요청은 막습니다.
- 새 입력의 빈 `localDate`는 ViewModel에서 저장 시점의 `TimeProvider.today()`로 채웁니다. 수정은 원래 날짜를 유지합니다.
- `wellness.db` 버전 3은 미응답을 SQL NULL로 저장합니다. 2→3 이전은 과거 값과 날짜를 그대로 복사하며, 과거 기본값을 미응답으로 추정하지 않습니다.
- 통계는 해당 지표에 실제 응답한 기록만 사용합니다. 수면·활력 패턴은 두 항목을 모두 응답한 날짜만 포함합니다.
- 새 서버·분석 이벤트는 추가하지 않으며 기존 백업 비활성 설정을 유지합니다. 아침 발기 기록을 의학적 진단으로 해석하지 않습니다.

## 검증

`./gradlew :app-nanda:testDebugUnitTest :core:data:testDebugUnitTest :core:database:testDebugUnitTest`

기록 검증·자정 경계·재조회·수정·삭제·실패 후 재시도·중복 제출·미응답 통계 및 SQLite 데이터 이전을 검사합니다. 데이터 이전 테스트는 호스트 JVM SQLite로 실제 DB를 열고 닫습니다. JVM 모듈 `core:model`, `core:domain`, `core:data-api`에는 `testDebugUnitTest`가 없어 다른 테스트 작업으로 대체하지 않습니다. Compose UI 테스트는 추가하지 않습니다.

수동 화면 확인 항목: 상세 영역 펼침/접힘, 화면 회전 후 입력 유지, 선택 해제, 삭제 취소, 개인정보 숨김, 큰 글꼴에서 입력/저장 접근성. 이 문서는 수동 확인 완료를 의미하지 않습니다.
